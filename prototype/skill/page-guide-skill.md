# Page Guide Skill（初版）

> 第一阶段历史方法，不是运行入口。2026-10-01 当前产品使用 LEARN02/03 在对话中理解网页与标注对象；不要求先生成完整教程或独立知识卡。以下原型方法与合同保留供追溯。

本 Skill 教 AI 如何把一次页面会话变成可验证的注释指引。消费者是执行生成的 AI Agent；输入是页面结构快照，输出是 guide.json。

## 生成流程

1. **先读页面骨架，再下钻控件。** 先用标题和分区把页面组织成「区块 → 控件」的层级；裸控件列表没有语义，禁止直接生成注释。
2. **选择值得注释的元素。** 优先覆盖：用户完成当前任务必经的入口、含义不自明的参数控件、容易误用的开关、列表主操作。跳过纯装饰和重复项。
3. **选择抗失效的定位策略。** 优先级：stable text 锚点 > aria/placeholder/label > 结构路径。同一元素给主定位和一个备选定位。
4. **注释写三层信息**：这个元素是什么；在当前任务里该怎么用；它和相邻项的关系。禁止只复述控件名。
5. **每条指引必须验证。** 渲染前用定位策略在真实页面命中；未命中就重新观察修正，不允许渲染推测结果。
6. **失效要显性。** 无法修复的条目标记为 expired，渲染层必须显示指引过期，不允许沉默消失。

## guide.json 合同（初版）

```json
{
  "task": "任务名",
  "pageBinding": { "urlPattern": "URL 匹配规则", "landmarks": ["页面地标文本"] },
  "steps": [
    {
      "id": 1,
      "primary": { "strategy": "placeholder|text|css", "value": "..." },
      "fallback": { "strategy": "css", "value": "..." },
      "comment": "三层注释"
    }
  ]
}
```
