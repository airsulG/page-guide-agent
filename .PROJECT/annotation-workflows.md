# 网页探索、对话讲解与说明改进工作流

当前核心分工是：Karl 持续对话、理解并操作，Codex 观察页面、选择对象、解读并核对结果。自主探索与对话讲解共享组件知识；文字质量和具体化检查负责让这份知识可信、可用。插件不提供预设路径播放器。

## 共同前置条件

核对用户指定浏览器与页面，取得当前页面句柄，观察实际组件并读取库存。当前会话使用正式 `guide:call`；原生工具是否可用以当前发现为准。按[协议](protocols/mcp-annotations.md)注册说明，保留来源、未知口径与覆盖缺口。换页、重载或节点失效后重新观察与注册，不沿用旧组件 ID。

全量目标是覆盖当前状态中有意义的组件，不是达到一个数量。按导航、输入、指标、表格、图表和辅助操作分区核对；记录已覆盖、待核实、无法定位及尚未加载的对象。折叠区域在展开后补查，图表无法准确定位的内部点只在对话解释。泛化后备文字不计为内容质量已通过。

库存超注册上限时，明确本次覆盖范围及未注册对象，不静默截断或冒称整页覆盖。结果核对同时检查当前筛选范围及实际数值，不能只看排序箭头；没有显式排序状态时，记录已观察到的顺序，不猜控件模式。

## 自主探索

1. 注册当前页面知识后，核对默认无框、角标或卡片。
2. Karl 悬停感兴趣的组件，出现组件框与附近深色磨砂卡。已指向对象同样可悬停；页面同时只显示一张卡，移开收起，进入卡片可继续阅读或复制。
3. 需要深入时，Karl 复制标题和组件 ID 到对话。Codex 核对当前页面及注册对象，回答这个组件的具体问题；复制的旧 ID 无效时重新定位，不猜对象。
4. 问题需要操作或比较时进入对话讲解；只需理解时直接讲明白。结束后保留自主悬停能力。

通过条件：默认原样、命中正确组件、卡片不重复、内容对应对象、复制身份准确、原业务操作仍可使用。区域未覆盖时明确补查，不称整页已经完成。

## 对话指向讲解

1. 从当前问题提出一个有价值的有限目标。按目标相关性、判断后果、是否需要串联多个组件、操作后能否核对结果选择任务；没有目标时提出可调整起点，不要求填写策略问卷。
2. 说清这次要得到什么、为什么选择这些对象、由谁操作以及怎样判断完成。只展示当前需要的对象，不提前铺满所有阶段。
3. 用 `show` 选择对象，按返回编号在对话解释用途、机制与判断。选择本身只常驻框和角标，不展开多张卡；悬停仍可查看单张说明。编号是当前选择组的操作／讲解顺序，不是永久组件身份；替换或移除后重新核对对应关系。
4. Karl 理解并操作，Codex 等待实际操作或反馈后观察结果。结果未出现、范围不符或对象失效时先调查，不能把点击或标注成功当成目标完成。用户追问可改变顺序和解释深度。
5. 按结果追加、替换或撤下对象，必要时重新注册。完成时给出实际观察与目标结论，再空选择撤下指向，确认角标消失且自主悬停仍可用。

通过条件：目标明确、指向真实、编号对应、用户操作确实发生、结果支持结论、发生变化时调整、结束清理。仅由 Codex 代操作的检查标为技术演练，不代替 Karl 参与的完整验收。

## 文案质量检查

新注册、组件变化或用户反馈时执行；方法和完整案例见[标注写作](annotation-writing.md)。

1. 明确当前组件引发的问题，核对标签、单位、时间、所在区域和实际行为，取得必要来源。平台口径未知时保留未知。
2. 标题直接说对象及用途；正文先说明含义，再补真正影响判断的关系和必要动作。数字类解释形成机制，入口类解释目的地及能完成的具体工作，不强迫每条都有数字例子。
3. 按 Apple 技术支持式表达读回：常用词、完整句子、一段一件事、条件靠近相关动作、名称一致。行家感来自重要关系和具体观察，不来自术语或强硬语气。
4. 逐条核对对象对应、事实依据、知识增量、操作用途和阅读清楚程度。指出用户读完新增的具体判断；只复述标签或使用通用提醒的文字列为待完善。
5. 写回说明及原任务记录，重新注册后检查真实卡片；事实改变时更新，用户理解反馈继续修正。文本检查、浏览器展示和用户理解分别记录。

## 不够具体时的修正

1. 接收复制组件、疑问或主动检查发现。先确定精确对象，再保留错误标题、正文及不适用之处。
2. 判断原因：多个功能共用模板、规则误匹配、无名称、列标题与单元格混淆，或缺少真实功能证据。检查相同规则覆盖的其他对象。
3. 分别观察或查证各对象用途。未知功能先补查，不用“打开相应栏目”冒充完成说明，也不把所有链接当作账户。
4. 拆分或修正规则，写各自能完成什么、产生什么结果及必要区别，再执行文案质量检查。修一组同因问题，不只改用户指出的一个标题。
5. 重新注册并真实悬停原对象及同组代表对象，核对标题、正文、复制 ID。保存来源和检查结果；未解决对象继续列为待完善。

## pump.fun 完整验收任务

目标：理解持有人表的供应量占比，并通过排序检查较大持仓是否靠前。只做公开数据查看，不连接钱包或交易。

先自主悬停列标题，查看定义与钱包分布的区别；再在对话指向①供应量占比列标题，解释点击排序的用途，请 Karl 操作。操作后核对排序方向及前几行占比，保留列标题，用 add 追加代表性单元格，按返回编号（通常为②）解释当前钱包的比例；不将钱包数等同人数，不在分母未核实时补造口径。必要时请 Karl 再点击切换方向并重新观察。最终形成当前排序结果及能支持的判断，撤下编号，保留悬停。缺少 Karl 操作时记录等待，不写通过。
