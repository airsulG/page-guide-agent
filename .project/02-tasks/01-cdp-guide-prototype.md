<<<<<<<<<<<<<<<<<<<< 01A Objective Decomposition 目标对象定义 <<<<<<<<<<<<<<<<<<<<

- 目标对象：第一阶段最小原型，覆盖 Chrome 页面端、本机 Agent 通道、指引渲染与示例任务文件。
- 结果维度：AI 对一个此前未配置过的复杂页面产出覆盖任务关键元素、经验证命中的注释指引并渲染（对应 PRD 验收标准 1）。
- 排除项：任务步骤推进、用户交互反馈、AI 自动点击、云端服务、通用测试框架。
- 交付形态：可运行原型、一份示例任务文件、一次真实页面的验证记录。
- 来源：PRD 1.4 / 1.7 / 1.10 与本对话中 Karl 的确认。

<<<<<<<<<<<<<<<<<<<< 01 PRD 目标和边界 <<<<<<<<<<<<<<<<<<<<

- 用户目标：在一个复杂页面上，不写任何人工配置，由 AI 会话内产出并在页面渲染出正确命中的注释指引。
- 成功标准：PRD 验收标准 1 成立；同时产出“任务为主对象”与“网页为主对象”的恢复成本比较。
- 不做事项：见 01A 排除项；不修改 PRD 产品边界，结论只写回证据区。
- allowed files：`.project/02-tasks/`、`.project/05-prototypes/`（原型代码与验证记录）、PRD 证据区写回。
- Goal 关系：当前无 active Codex Goal；本 Task 直接推进 PRD 第一阶段。
- 验证预算：以最小内聚验证为准，不为原型搭建通用测试框架；每轮验证对应一条验收证据。

<<<<<<<<<<<<<<<<<<<< 02 当前状态和目标状态差异 <<<<<<<<<<<<<<<<<<<<

**已成立事实**：PRD 需求初版已记录；产品不限网站名单、复合组件结构、必须持久化已经 Karl 确认。

**候选事实与未知**：持久化顶层对象（任务为主 vs 网页为主）；CDP 连接归属（本机服务直连 vs 扩展采集后转发）；指引 Skill 的具体工作法；目标验证页面选型。

**差距**：原型完全不存在，验收标准 1 无任何证据。

**证明条件**：真实页面上出现经验证命中的渲染指引，且成果可从本地文件二次恢复。

**结论去向**：验证结论写回 PRD 的组件方案、技术边界与已验收证据；不成立的方向明确不晋升。
