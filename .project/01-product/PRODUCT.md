# PRODUCT

本文件是产品总定义权威源，保存 Karl 已确认的产品存在性判断、产品定位、核心对象、最终成立状态、跨模块规则和模块索引。一个用户能力模块的一份 PRD 放在同目录，并由本文件维护入口；模块内尚未稳定的问题、候选方向与当前缺口保留在该 PRD 的当前交付区。

## 1. 产品存在性与用户现实

用户面对 Semrush 等复杂 Web 工具时，通常不知道页面功能的作用、参数应该怎样填写，以及完成目标应该先做哪一步。今天的替代方式是离开页面询问 AI、查文档或看教程，再靠自己把文字答案映射回界面；问题在这一步发生断裂。

本产品把 AI 的理解直接放回当前网页：AI 通过 CDP 观察页面，在会话里生成和验证指引，再由 Chrome 页面端渲染箭头、注释和后续步骤。有效结果会保存到本地文件，下一次可以复用；页面变化后由 AI 在新会话里检查并修复。

## 2. 产品定义

- 产品名：`51-page-guide-agent`
- 一句话定义：用户在任意网页上通过对话让本地 AI Agent 理解页面结构，并在页面上直接渲染分步指引；学习成果沉淀为本地任务文件，越用越准。
- 核心价值：把「看懂复杂网页并完成任务」从离开页面求助文档，变成页面上的即时视觉指引；会话内自愈，无需人工维护配置。
- 用户角色：当前阶段为 Karl 本人；面向所有需要使用复杂 Web 工具但不熟悉其界面的用户。
- 不做事项：AI 自动替用户点击（第一阶段）；云端账号与多端同步；预置网页白名单或静态指引库；通用爬虫/数据提取。

## 3. 产品原则

- **不限网站名单**：不以预置白名单定义支持范围；只要浏览器与 CDP 能实际观察和注入页面，就进入产品能力域。
- **用户操作，AI 教学**：产品先帮助用户理解并完成任务，不在第一阶段替用户点击或提交。
- **会话内验证**：AI 生成的元素定位和注释必须在当前页面实际验证，不能把推测直接渲染给用户。
- **本地持久化**：指引成果和网页关联保存在人和 Agent 都能读取的本地文件中。
- **Skill 独立演进**：页面理解与任务指引方法沉淀为独立 Skill，不与某个模型或某个网站绑定。

## 4. 最终成立状态

用户在一个此前没有配置过的复杂网页上发起对话后，产品能够理解页面、把解释准确指向真实元素，并引导用户完成一项多步骤任务。生成结果会关联到本地文件；同一任务再次打开时可以直接恢复，页面变化时可以自动检查并修复失效部分。

产品由 Chrome 页面端、本地后端解析与运行服务、AI Agent + 指引 Skill、本地持久化文件共同组成。具体技术边界和当前交付从模块 PRD 恢复。

## 5. 核心对象

- **任务文件**：持久化主对象，以「完成某件事」为单位，内含 task.md 与 guide.json，本地文件、可 diff、可进 Git。
- **页面绑定 / 步骤 / 元素选择器**：任务文件内的三层绑定结构（粗 → 中 → 细），决定页面匹配与元素定位。
- **指引会话**：AI Agent 的一次观察-生成-验证-修复-写回过程，是配置的生产者而非持久对象。

完整对象关系见模块 PRD：`01-product/page-guide-agent.md`。

## 6. 页面与交互规则

- 指引直接出现在当前网页，不要求用户离开页面阅读另一份教程。
- 每条注释必须明确指向一个真实页面元素；无法确认时显示失效或待修复状态，不允许错误指向。
- 第一阶段以结构识别和页面注释为主；第二阶段才让用户操作反馈推动“下一步”。
- 用户可以启动、暂停或结束一次指引，不因 Agent 会话存在而失去对网页的正常控制。
